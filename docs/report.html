1. 概要

日本語で「青いボールを確認してから、緑の箱の前で止まって」のように指示すると、大規模言語モデル（Claude）が指示を解釈して行動計画を立て、 二輪ロボットがカメラ画像を頼りに目標を探し、近づき、止まるシステムを作成した。シミュレータには MuJoCo を使い、Windows 上だけで動作する。

2. 目的・背景

家庭や倉庫で働くロボットには、専門家でない人が普段の言葉で指示できることが求められる。一方で、言語モデルに直接モーターを動かさせると、 誤った出力がそのまま危険な動作につながる。そこで本課題では、言語モデルには「何をするか」の計画だけを任せ、 「どう動くか」はカメラによる認識と決まった制御で確実に行うという役割分担を目標とした。

3. システム構成

日本語の指示 ──▶ Claude（行動計画）──▶ 計画の検証 ──▶ 実行器 │ 前方カメラ（色画像＋距離画像）──▶ 色と距離の認識 ──▶ 移動制御 ──▶ 二輪ロボット
部分内容
シミュレータMuJoCo 3.15。床と壁の部屋に赤い箱・緑の箱・青い球を配置。差動二輪ロボットの前方に RGB-D カメラ（色画像と距離画像）を搭載。
計画（AI）Claude（claude-opus-5-5）に指示を渡し、ツール呼び出し submit_plan で計画を受け取る。動作は search（探索）・approach（接近）・stop（停止）の3種類、対象は red / green / blue に限定。
計画の検証受け取った計画をプログラム側で再検査（動作数1〜8、許可した動作と色のみ、最後は必ず stop）。不合格ならロボットを動かさない。
認識色画像から指定色の画素を抽出し、画像内の左右位置と、距離画像から目標面までの距離を求める（ルールベース）。
移動制御見えなければその場で回転して探索。見えたら画像の中央に合わせながら前進し、目標面まで約 0.65 m で停止。
記録実行の様子を MP4 に保存（指示・計画・現在の手順・前方カメラ映像を重ねて表示）。

4. AI の役割

AI（Claude）は日本語の指示を、実行できる行動計画に変換する役割を担う（推論のみで、追加学習は行っていない）。 例えば「確認してから」は目標を見つけるだけの search、「前で止まって」は近づいて止まる approach と、指示の意味の違いを計画に反映する。 ロボットにできない指示（物を運ぶなど）には、動かずに stop だけの計画を返す。画像認識は AI ではなくルールベースである。

5. 工夫した点

  1. AI に任せる範囲を限定した安全な設計。参考にしたサンプル「ChatGPT API による自然言語ロボット操作」は言語モデルの出力でロボットを動かす構成だが、本課題では出力を3種類の動作と3色に限定したスキーマで受け取り（strict モード）、さらにプログラム側で検証してから実行する。誤った計画や失敗した動作があれば、残りの実行を中止する。
  2. カメラ画像だけで目標に到達する。シミュレータが持つ物体の正確な座標は移動制御に使わず、前方カメラの色画像と距離画像から目標の方向と距離を求めて動く。実機に近い条件で作り、座標は動作検証の判定だけに使った。
  3. 指示の意味の違いを動作の違いにした。「確認する」（見つけるだけ）と「〜の前で止まる」（近づいて止まる）を別の動作として計画させた。
  4. できない指示は断る。未対応・曖昧な指示では停止のみの計画にするよう指示し、「コーヒーを持ってきて」では実際に停止のみが返った。
  5. Windows だけで再現できる構成。参考サンプル「ROS2 と Gazebo の連携によるロボット操作」は Linux 上の ROS 2 を使うが、本課題は MuJoCo と Python のみで構成し、pip install だけで再現できるようにした。
  6. デモ動画を自動生成。シミュレーションの描画から直接 MP4 を作るため、画面収録が不要で、個人情報が映り込むこともない。

6. 結果

(1) 色認識による探索・接近（AI なし、初期位置から各色1回）

目標到着までの時間（シミュレーション時間）停止位置（ロボット中心〜目標中心）
赤い箱6.3 秒1.127 m
緑の箱8.5 秒1.125 m
青い球16.4 秒1.083 m

停止距離 0.65 m に、目標の半分の大きさ（0.25 m）とロボット中心から前端まで（約 0.22 m）を加えた約 1.12 m とほぼ一致した。

(2) Claude による計画と実行

指示Claude の計画結果
赤い箱へ行って探索：赤 → 接近：赤 → 停止正しい計画（計画のみ確認）
青いボールを確認してから、緑の箱の前で止まって探索：青 → 探索：緑 → 接近：緑 → 停止完走（青を発見 9.0 秒、緑を発見 4.5 秒、緑に接近 7.8 秒）
コーヒーを持ってきて停止動かずに停止

このほか、計画の検証・実行の中止・Claude 応答の検査を確かめる単体テスト4件がすべて成功した。 なお、Claude を使った試行はそれぞれ1回のみで、多数回の成功率は測っていない。

7. 課題と考察

  • 認識の限界：色だけで判定しているため、同じ色の物体が複数ある場合や、形の区別（箱か球か）はできない。物体検出モデルや、画像を理解できる言語モデルを使えば改善できる。
  • 障害物回避なし：目標までの間に障害物がない部屋を前提にしている。
  • 探索の効率：探索は常に左回りのため、右側の目標（青い球）は見つけるまでに時間がかかった。見失った方向へ回るなどの改善が考えられる。
  • 計画が一方通行：現在は最初に立てた計画を順に実行するだけで、失敗したときに Claude が計画を立て直す仕組みはない。実行結果を Claude に返して再計画させるのが次の発展である。
  • 評価の規模：試行回数が少ないため、多様な指示と多数回の試行で成功率を測る必要がある。
  • 考察：言語モデルに計画だけを任せ、出力を限られた動作に絞って検証する設計により、言語モデルの柔軟さ（指示の意味の違いを読み取る、できないことを断る）と、ロボット動作の確実さを両立できた。

8. 実行方法

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env      （.env に ANTHROPIC_API_KEY を設定）
.\.venv\Scripts\python.exe src\main.py --instruction "赤い箱へ行って"

詳しくはリポジトリの README を参照。API キーはリポジトリに含めていない。
